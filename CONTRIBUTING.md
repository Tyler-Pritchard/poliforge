# Contributing to PoliForge

First off, thank you for your interest in contributing to **PoliForge** — an open-source initiative to transform how political campaigns are run and who gets to run them. This project welcomes engineers, designers, researchers, activists, and civic technologists of all backgrounds.

We are in early-stage development, so **your ideas and skills can have an outsized impact** on the system design and implementation.

---

## 🧭 Project Values

- **Transparency**: All code, documentation, and AI generation processes should be explainable and reviewable.
- **Accessibility**: We aim to remove barriers to entry in both politics and software development.
- **Modularity**: Each service should be independently deployable, replaceable, and maintainable.
- **Civic Neutrality**: Tools, not ideology. We build systems that empower others to advocate for their communities.

---

## 🛠 Ways You Can Contribute

### 🧑‍💻 Engineering
- Help define and build microservices
- Contribute to data ingestion, RAG pipelines, or LLM tooling
- Work on the API gateway and service communication layers
- Set up local dev tooling (Docker, CI/CD, logging)

### 📐 UX / UI / Docs
- Help mock up dashboard interfaces or content editors
- Improve README, service guides, and technical documentation

### 🧠 Strategy & Research
- Map campaign workflows to technical features
- Research legal/ethical compliance requirements
- Analyze API/data source viability (e.g., OpenStates, FEC, local laws)

### 🧪 Testing
- Create integration test suites
- Help implement service health checks and observability dashboards

---

## 🔧 Local Development (Coming Soon)
Each microservice will have its own README with setup instructions. In general:

1. Clone this repository and any services you want to work on
2. Follow `infra/docker-compose.yml` to spin up local services
3. Use the shared `.env` template or service-specific `.env` files

---

## 📬 Getting Started

1. Fork this repository (or any service repo)
2. Open an issue or join an active one to express interest
3. Submit a PR following our commit format and review guidelines (TBD)
4. Use clear commit messages and document major decisions in PRs

---

## 📎 Communication

- Issues and discussions will live in GitHub for transparency
- For more involved work, please include architecture sketches, diagrams, or workflow drafts when proposing a change
- Community chat (Discord/Matrix/email list) will be established once initial contributors onboard

---

## ⚖️ Code of Conduct

We follow the [Contributor Covenant](https://www.contributor-covenant.org/) for behavior expectations. Respect and inclusion are non-negotiable. The goal is to empower good people to build tools that empower others.

---

Thank you again for contributing. This is not just software — it’s scaffolding for a more participatory democracy.
